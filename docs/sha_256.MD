 **SHA-256** (Função de Hash).

## 1. O Conceito Fundamental: O que é uma Função Hash?

É muito comum as pessoas confundirem Criptografia com Hash, mas eles têm propósitos totalmente diferentes:

* **Criptografia (ex: RSA, AES):** É uma via de **mão dupla**. Você embaralha os dados com uma chave, e pode desembaralhar com a chave correspondente. A informação original é preservada.
* **Hash (ex: SHA-256, MD5):** É uma via de **mão única**. Funciona como um "triturador de papel matemático". Ele pega um documento de qualquer tamanho (uma palavra ou um livro inteiro de 500 páginas) e o transforma em uma "impressão digital" (resumo) de tamanho fixo. 

**Características vitais do SHA-256:**
1. **Determinístico:** A mesma entrada sempre gera o mesmo hash.
2. **Tamanho fixo:** A saída sempre terá 256 bits (representados como 64 caracteres hexadecimais).
3. **Irreversível:** É matematicamente inviável (impossível com a tecnologia atual) descobrir a mensagem original a partir do hash.
4. **Efeito Avalanche:** Mudar uma única vírgula no arquivo original altera o hash final de forma drástica e imprevisível.

## 2. A Matemática do SHA-256: Uma Dança de Bits

Enquanto o RSA baseia-se na dificuldade de fatorar números primos gigantes (Teoria dos Números), o SHA-256 baseia-se em **Operações Lógicas Bit a Bit** (`Bitwise Operations`).

O algoritmo processa a mensagem em blocos de **512 bits** por vez, passando cada bloco por **64 rodadas de compressão**.

### O Passo a Passo Matemático:

1. **Preenchimento (Padding):** O computador pega a sua mensagem e a converte para binário (0s e 1s). Ele adiciona um bit `1` no final, seguido de vários `0`s, até que o tamanho falte exatamente 64 bits para ser um múltiplo de 512.
2. **Adição do Tamanho Original:**
   Nesses 64 bits finais, o algoritmo anota qual era o tamanho exato da mensagem original. Agora temos blocos perfeitos de 512 bits.
3. **Valores Iniciais (H):**
   O algoritmo começa com 8 "copos medidores" (variáveis chamadas de `a` até `h`), preenchidos com valores constantes derivados das raízes quadradas dos 8 primeiros números primos.
4. **Constantes (K):**
   Durante as rodadas, ele usa 64 valores constantes derivados das raízes cúbicas dos primeiros 64 primos.
5. **A Roda de Compressão:**
   Para cada bloco de 512 bits, o algoritmo roda 64 vezes. Em cada rodada, os bits são "embaralhados" usando funções lógicas como:
   * **XOR ($\oplus$):** Ou exclusivo.
   * **AND ($\land$):** E lógico.
   * **ROTR (Right Rotate):** Pega os bits da ponta direita e os empurra de volta pela ponta esquerda (rotação circular).

### Camada 1: Constantes

Apenas declaramos as tuplas contendo os valores hexadecimais que o padrão oficial do algoritmo (criado pela NSA) exige.

### Camada 2: Funções Lógicas (`Bitwise`)

Aqui definimos as funções atômicas. Por exemplo, a função de Maioria (`maj`) analisa três bits e retorna o valor que aparece mais vezes. As funções `sigma` realizam múltiplas rotações e XORs simultaneamente para garantir a dispersão extrema dos dados.

### Camada 3: O Coração do Algoritmo (`gerar_sha256`)

É o módulo mais denso. Ele:

1. Pega a string e converte para um vetor de `bytes`.
2. Faz o "Padding" (adiciona o 0x80 que representa o bit `1`, e preenche com 0s).
3. Divide em pedaços de 64 bytes (512 bits).
4. Aplica o loop principal de 64 iterações.
5. Soma o resultado ao hash temporário.
6. Ao final de todos os blocos, formata as 8 variáveis inteiras de 32 bits em uma única string de 64 caracteres hexadecimais (256 bits).

## 4. Por que usaríamos isso no Mundo Real?

Na vida real, **nós nunca armazenamos a senha de um usuário como texto puro no banco de dados**.

Se a senha da Alice for `senha123`, nós rodamos o SHA-256 e salvamos apenas o hash:
`ef92b778bafe771e89245b89ecbc08a44a4e166c06659911881f383d4473e94f`

Quando a Alice tenta logar novamente, aplicamos o hash na senha que ela digitou e comparamos os hashes. Se o banco de dados for invadido, o hacker verá apenas os hashes triturados e não saberá a senha original da Alice!

*Nota do Professor:* Hoje em dia, adicionamos um "Salt" (um texto aleatório) antes de gerar o hash da senha, para proteger contra ataques de dicionário (Rainbow Tables). Algoritmos mais recentes e lentos, como o `Argon2` ou `bcrypt`, são preferidos para senhas, mas o SHA-256 ainda é amplamente usado em assinaturas digitais, integridade de arquivos e até na mineração de Bitcoin!
